# 2026-10-14 工作日志

## 机械臂控制链路修复（方案A：留在 Humble + Fortress）

背景：项目从 Gazebo Classic 11 迁移到 Gazebo Sim Fortress (6.18)，机械臂键盘控制一直无反应。经多轮排查定位根因：

### 环境版本栈
- ROS2: Humble
- Gazebo: Fortress (gz-sim 6.18.0)
- ros_gz: ros-humble-ros-gz（绑 Fortress）
- 参考 PDF/别人仓库是 Jazzy + Harmonic (gz-sim 8)，插件和话题命名有代差

### 踩过的坑（全部是"Harmonic 思路写进 Fortress"导致）
1. `gz.msgs.Double` → Fortress 用 `ignition.msgs.Double`
2. `gz sim` 启动 → Fortress 用 `ign gazebo`
3. `<cmd_topic>` 自定义话题 → Fortress 6.18 不支持，必须用默认 `/model/<model>/joint/<joint>/0/cmd_pos`
4. 插件名 `ignition-gazebo-*` vs `gz-sim-*` → 6.18 认 `gz-sim-*`（diff-drive 用 gz-sim 一直活着）

### 最终方案A（已实施）
1. `model/myrobotv52.sdf`：8 个 JointPositionController 插件名改回 `gz-sim-joint-position-controller-system` + `gz::sim::systems::JointPositionController`，cmd_topic 改回默认 `/model/vehicle_blue/joint/<joint>/0/cmd_pos`
2. `launch/my_robot_orchard_launch.py`：8 条 arm bridge 参数改成默认话题名，parameter_bridge 节点加 8 个 remappings（默认话题 → /arm/*_cmd）
3. 键盘脚本 `scripts/arm_keyboard_teleop.py` 不变，继续发 /arm/*_cmd

### 关键教训
- Gazebo Classic → Fortress 迁移，插件体系完全不同（libgazebo_ros_* → gz-sim-*-system）
- Fortress 的 ros_gz_bridge 参数语法：`<topic>@<ros_type>]<gz_type>`（ROS→GZ）、`<topic>@<ros_type>[<gz_type>`（GZ→ROS），`[`/`]` 紧跟在 ros_type 后
- JointPositionController 在 Fortress 不支持 `<cmd_topic>`，只能用默认 /0/cmd_pos 话题 + bridge remappings
- 排查顺序：插件加载 → 话题是否存在（ign topic -l）→ 订阅者是否存在（ign topic -t X -i）→ 手动发消息测试（ign topic -t X -m ignition.msgs.Double -p "data: 0.5"）
