## 果园苹果掉落问题 — 采用 gazebo_ros_link_attacher 插件物理附着

### 问题
1. 苹果 spawn 到树冠后受重力掉落（悬空无支撑）
2. 苹果出现太慢（launch 里 TimerAction 硬编码 8s 延迟）

### 最终方案：gazebo_ros_link_attacher 插件（不用禁用重力）
用户坚持真实物理附着，放弃 `<gravity>false</gravity>` 权宜方案。

### 关键坑（重要，避免重复踩）
1. **服务名**：实际是 `/attach` 和 `/detach`（插件用相对名 "attach"/"detach"，
   解析到根命名空间）。README 写的 `/link_attacher_node/attach` 是**错的**，
   会导致脚本一直 waiting 等不到服务、一个苹果都不生成。
2. **服务类型**：`gazebo_ros_link_attacher/srv/Attach`
   字段：`model_name_1, link_name_1, model_name_2, link_name_2 -> bool ok`
   （不是 SpawnEntity！之前用错类型导致静默失败）
3. **插件是 WorldPlugin**：必须直接放在 `<world>` 下作为 `<plugin>`，
   不能嵌套在 `<model>` 里。之前放错位置导致插件不加载。
4. **⚠️ 库文件名**：`libgazebo_ros_link_attacher_plugin.so`（带 `_plugin` 后缀！）
   README 写的是 `libgazebo_ros_link_attacher.so`，那是旧的、错的。
   以 CMakeLists 的 `add_library(${PROJECT_NAME}_plugin ...)` 为准。
   包自带 world 文件用的 plugin name 是 `ros_link_attacher_plugin`。

### 安装（ROS2 Humble，Ubuntu 22.04）
```sh
cd $ROS2_WS/src
git clone https://github.com/Brazilian-Institute-of-Robotics/gazebo_ros_link_attacher.git
cd $ROS2_WS
source /opt/ros/humble/setup.bash
colcon build --packages-select gazebo_ros_link_attacher --event-handlers console_direct+
source install/setup.bash
```

## 二期 STEP 1：4-DOF 吸盘机械臂建模 + 手动控制

### 决策
- 控制方案：**Gazebo SDF 插件**（不引入 ros2_control）
  - `libgazebo_ros_joint_state_publisher.so`（发 /joint_states 供 TF）
  - `libgazebo_ros_joint_pose_trajectory.so`（订阅 /set_joint_trajectory 话题，运动学置位）
  - 需 `sudo apt install ros-humble-gazebo-plugins`
- 臂型：4-DOF 自建几何体（圆柱）+ 吸盘末端（fixed link）
  - joint1_base_yaw(基座Z) / joint2_shoulder_pitch(Y) / joint3_elbow_pitch(Y) / joint4_wrist_pitch(Y)
  - 挂载点：base_link 上 `(-0.15, 0, 0.0835)`
  - 竖直朝上时吸盘顶离地 ~1.74m，覆盖 1.42–1.62m 苹果

### 改动文件
- `model/myrobotv52.sdf`：加 5 link + 5 joint + 2 插件
- `model/myrobotv52.urdf`：同步加 5 link + 5 joint（供 robot_state_publisher 播 TF，名字必须与 SDF 逐字一致）
- setup.py/launch 无需改（glob 已覆盖）

### 关键坑（必须遵守）
1. **关节轴 `use_parent_model_frame` 必须 false**！用 true 会让肘/腕轴不随大臂旋转。
2. **每个 revolute 的父子 link 都要有 `<inertial>`**，否则 Gazebo 报 "Joint does not exist"。
3. **SDF 插件参数是 snake_case**：`update_rate`/`joint_name`（ROS1 的 updateRate/jointName 不认）。
4. SDF 关节不写 `<pose>` → 关节原点 = 子 link 的 model pose（沿用现有 diff-drive 风格）。
5. model 名保持 `vehicle_blue`（link_attacher 认 model 名，不是 spawn 的 `-entity myrobotv5`）。

### 手动控制命令
```bash
ros2 topic pub -r 20 /set_joint_trajectory trajectory_msgs/msg/JointTrajectory \
"{joint_names: ['joint1_base_yaw','joint2_shoulder_pitch','joint3_elbow_pitch','joint4_wrist_pitch'],
  points: [{positions: [0.0, -0.7, 1.3, 0.4], time_from_start: {sec: 2, nanosec: 0}}]}"
```
（-r 20 持续重发以保持姿态；该插件不模拟力矩）

### 校验结果
- SDF/URDF XML 格式 OK；机械臂 link/joint 命名两边逐字一致；惯量齐全；父子 link 解析通过。

## 视觉调整：果树按 0.75 缩小（车不动）

### 决策
- 问题：树总高 2.2m、树冠球直径 1.3m，与 0.67m 长的底盘视觉失衡。
- **只缩树，绝不动车**：动车会牵连 `diff_drive` 的 `wheel_separation`/`wheel_radius`、
  Nav2 footprint、spawn 高度 `z=0.8`、雷达高度，威胁一期已跑通的导航。

### 改动（缩放系数 s = 0.75）
- `model/tree_model/model.sdf`：
  - 树干 radius 0.08→0.06，length 1.2→0.9，pose z 0.6→0.45
  - 树冠 radius 0.65→0.4875，pose z 1.55→1.1625
  - 惯量按 s² 缩放；树总高 2.2→**1.65m**
- `scripts/spawn_apples.py`：`APPLE_OFFSETS` 整体 ×0.75 → z = 1.065 / 1.215 / 1.14
- `model/myworld_orchard.sdf`：仅更新注释（树高 1.65m）

### 不受影响
- 世界文件 9 棵树的 `<include>` pose 不用改（树基座在 z=0）
- `tree_canopy` link 名不变 → `/attach` 附着逻辑完全不变
- 机械臂更够得着（苹果降到 ~1.1m，臂展 ~1.45m）

### 校验

## 启动报错：gzserver `Address already in use`
- 根因：上次 gzserver 未干净退出，占用 Gazebo 主端口 **11345**（用了窗口 X 关而没 Ctrl+C）。
- 解决：
  ```bash
  killall -9 gzserver gzclient; pkill -9 -f gazebo; pkill -9 -f spawn_entity
  ss -lntp | grep 11345   # 无输出=端口已释放
  ```
- 预防：始终 `Ctrl+C` 关 launch。
